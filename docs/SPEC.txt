0. 合意済みの本番方針（2026-07-26）
--------------------------------------------------------------------------------

【運用要件】
- 誰が・どの端末から管理画面を編集しても、公開サイトが同じデータで更新されること

【データ永続化】
- LeagueData / SiteConfig / SeasonArchive を JSONB 1ドキュメントとして保存（正規化しない）
- 同一テーブル app_documents。主識別子は document_key:
    league | site | archive_{season}
- ライブのリーグデータは document_key=league を常に1件のみ。
  シーズン終了時は archive_{season} として保存（league 自体は次シーズン用に更新）
- SUPABASE_SERVICE_ROLE_KEY + NEXT_PUBLIC_SUPABASE_URL があるとき DocumentStore→Supabase
  未設定時は従来どおり data/league.json 等のファイル（ローカル開発）
- 楽観的ロック: integer version。保存時に expectedVersion 不一致なら 409 と案内文
  「他のユーザーが更新しました。最新版を読み込み、内容を確認してから再度保存してください。」
- 旧 supabase/schema.sql（正規化案）は現行アプリでは未使用

【認証】
- ローカルモード: ADMIN_PASSWORD（既定 blh2022）+ ADMIN_SECRET
- Supabase URL/Anon Key 設定時: Supabase Auth（メール+パスワード）に切替
- ドキュメント書き込みは service role（サーバのみ）。本番ではキーをクライアントに出さない
- 本番では ADMIN_PASSWORD / ADMIN_SECRET を必ず環境変数で設定

【公開方針】
- 公開ページに管理・実装寄りの文言を出さない
- /admin はトップからの導線なし（URL直打ち）。robots で disallow

4. データモデル（LeagueData）
--------------------------------------------------------------------------------

単一オブジェクト（src/types/index.ts）:

  season, lastUpdated
  teams[]                 id(UUID), teamNumber, name, shortName, color,
                          imageUrl?, players[], displayLeague? (A|B)
  rounds[]                節。type=league|other, held, resultsFinished,
                          participatingTeamIds, pointSettings?,
                          additionalMatches?, parentRoundId?
  roundAssignments[]      roundId × teamId × group(A–F)
  matches[]               roundId, group, home/away, scores, status, slotOrder
  playerAwards[]          節×選手の個人賞・欠席
  news[], reports[]
  standingsOverrides[]    手動順位上書き（API のみ・UIなし・使わない方針）

【重要な概念分離】
  displayLeague (A/B)     … 順位表の所属
  MatchGroup (A–F)        … その節の試合振り分け。D/E/F は追加試合枠
  論理節                  … 親 Round + linked 子（追加試合）を合算単位

5. ドメイン仕様（運用ルール）
--------------------------------------------------------------------------------

【チーム】
- UUID 固定。削除は運用上行わない
- teamNumber は保存時に配列順で再付番
- ②付き shortName は公開チーム一覧から除外
- 公開 /teams: 今季いずれかの節 participatingTeamIds に入ったチームを初期表示
  「ほかのチーム」で未出場登録チームを開閉

【節】
- league: 累計・ポイント対象
- other: 当日順位のみ（累計外）
- held: 非公開・累計外
- resultsFinished: 「入力フェーズ終了」印。ロックはしない
- 未入力試合があっても節終了可
- 節終了時: お知らせ自動追加「{節名} 試合結果を更新しました」
- 次の試合: 公開節のうち resultsFinished でない最初の節

【試合 status】
- scheduled / in_progress / completed / cancelled
- 順位・ポイント: completed かつ両スコア入力のみ
- in_progress は順位未反映（仕様）

【順位（A/B 累計）】
1. ランキングポイント降順
2. 勝数
3. 得失点差
4. チーム名

【本節・当日順位】
- 勝数 → 得失点差（ポイント制なし）

【ポイント内訳（デフォルトは pointSettings / pointSettings.ts）】
  ベースP 300（初参加節のみ・通算1回）
  勝率P   勝率%そのまま
  得失P   max(0, 得失点差)×X
  圧勝P   点差に応じた圧勝点×X（勝利時）
  ジャイキリP 前節同一リーグで5位以上上位に勝利で+1×X
              （初出場節のチームが関わる試合は対象外）
  奮闘P   下位30%チームの勝利×X
  試合回数P 節内試合数×X

7. 永続化（DocumentStore）
--------------------------------------------------------------------------------

【入口】
  getLeagueData() / 既存 save* … 呼び出し形は維持。内部が DocumentStore。
  src/lib/documentStore.ts … get/save/list/delete
  src/lib/documentKeys.ts … league / site / archive_{season}
  src/lib/supabase/service.ts … service role クライアント

【テーブル】 supabase/app_documents.sql
  document_key (unique), document_type, season, payload jsonb, version, updated_at
  RPC save_app_document … version 一致時のみ更新（不一致は 0 行→409）

【管理 API】
  GET /api/admin → LeagueData + documentVersion
  PUT /api/admin → expectedVersion 必須（league 系）。競合時 409
  GET /api/admin/archives → { archives, versions }

【初回投入】
  node --env-file=.env.local scripts/seed-app-documents.mjs
